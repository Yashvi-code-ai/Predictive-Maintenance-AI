# Predictive Maintenance AI

**Machine Failure Prediction using Explainable Machine Learning**

A reproducible machine-learning project using the [UCI AI4I 2020 Predictive Maintenance Dataset](https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset). It explores machine operating conditions, compares classifiers, evaluates failure-class performance, and provides a Streamlit demo.

> **Scope:** This is an educational prototype trained on the synthetic UCI AI4I 2020 dataset. It is not a certified industrial safety system. Report only metrics generated by running the project.

## Final measured results

The following results were obtained from the stratified 80/20 split (2,000 held-out test records; 68 machine-failure cases). Failure is the positive class.

| Model | Accuracy | Precision | Recall | F1-score | ROC-AUC |
|---|---:|---:|---:|---:|---:|
| Logistic Regression | 82.45% | 14.18% | 82.35% | 0.242 | 0.907 |
| K-Nearest Neighbours | 97.25% | 80.95% | 25.00% | 0.382 | 0.856 |
| Decision Tree | 94.70% | 37.66% | 85.29% | 0.523 | 0.915 |
| **Random Forest** | **97.25%** | **57.14%** | **76.47%** | **0.654** | **0.967** |
| Support Vector Machine | 91.75% | 27.85% | **89.71%** | 0.425 | 0.965 |
| Naive Bayes | 95.80% | 25.00% | 11.76% | 0.160 | 0.847 |

Random Forest is the selected primary model because it achieved the highest F1-score and ROC-AUC. SVM achieved the highest failure recall but generated more false alarms. Model selection considers the precision/recall trade-off, not accuracy alone.

## Dataset setup

Download the CSV from the [UCI AI4I 2020 dataset page](https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset) and save it as `data/ai4i2020.csv`.

The target is `Machine failure` (0 = no failure, 1 = failure). Predictors are `Type`, `Air temperature [K]`, `Process temperature [K]`, `Rotational speed [rpm]`, `Torque [Nm]`, and `Tool wear [min]`.

## Run the project

Run commands from the repository root. Each Python workflow can also be launched directly using the `python src/<file>.py` form shown below; the scripts resolve the repository root automatically.

```bash
# Dataset cleaning summary and split details
python -m src.preprocessing
python src/preprocessing.py

# Exploratory data analysis
python -m src.eda
python src/eda.py

# Baseline models: Logistic Regression and Decision Tree
python -m src.baseline_models
python src/baseline_models.py

# Random Forest evaluation and permutation importance
python -m src.random_forest
python src/random_forest.py

# Compare all six classification models
python -m src.model_comparison
python src/model_comparison.py

# Train and persist the pipeline used by the app
python train_model.py

# Start the Streamlit demo
streamlit run app.py
```

All dataset-dependent commands require `data/ai4i2020.csv`. The preprocessing command supports a custom CSV path:

```bash
python -m src.preprocessing --csv-path /path/to/ai4i2020.csv
```

The notebook is designed to work when Jupyter is launched from either the repository root or the `notebooks/` directory. It discovers the repository root, imports the shared preprocessing module, and saves generated files into the repository's `outputs/` directory.

## Models and evaluation

`python -m src.model_comparison` evaluates six classifiers on the same stratified 80/20 split. Evaluation includes accuracy, precision, recall, F1-score, ROC-AUC, and confusion matrices. Since failures are a minority class, do not select a model by accuracy alone. Consider missed failures (false negatives), false alarms (false positives), and the intended maintenance trade-off.

The notebook provides a guided three-model workflow, while `src/model_comparison.py` runs the full six-model comparison.

## Leakage prevention and preprocessing

The shared utilities in `src/preprocessing.py` validate the AI4I schema, remove exact duplicates and rows with missing targets, report missingness and IQR outliers, and exclude identifiers (`UDI`, `Product ID`) and failure-mode flags (`TWF`, `HDF`, `PWF`, `OSF`, `RNF`). Numeric values use median imputation and scaling; categorical values use most-frequent imputation and one-hot encoding inside each model pipeline.

## Explainability

`python -m src.random_forest` produces permutation-importance outputs under `outputs/`. Permutation importance estimates how shuffling one input feature affects the chosen evaluation score. It describes predictive usefulness on this evaluation; it does not establish causation.

## Limitations and future work

- AI4I is synthetic and may not represent every real industrial setting.
- Failure classes are imbalanced; the best threshold depends on the cost of missed failures versus false alarms.
- Model output probabilities are not necessarily calibrated real-world risks.
- Sensor conditions may omit maintenance history, environment, machine-specific differences, and operational costs.
- Before operational use, validate on real data, assess calibration and generalization, select thresholds on validation data, and establish monitoring and human review.
