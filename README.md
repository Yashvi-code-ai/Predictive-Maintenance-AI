# Predictive Maintenance AI

**Machine Failure Prediction using Explainable Machine Learning**

A reproducible machine-learning project using the [UCI AI4I 2020 Predictive Maintenance Dataset](https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset). It explores machine operating conditions, compares classifiers, evaluates failure-class performance, and provides a Streamlit demo.

> **Scope:** This is an educational prototype trained on a synthetic dataset. It is not a certified industrial safety system. Report only metrics generated by running the project.

## Project workflow

1. Define the binary classification problem and objectives.
2. Inspect the dataset, target distribution, correlations, missing values, duplicates, and potential outliers.
3. Clean duplicate rows and rows with missing targets; report feature missingness and outliers.
4. Exclude identifiers and failure-mode flags that leak the target.
5. Create a stratified 80/20 train/test split using random seed 42.
6. Fit preprocessing and classifiers using training data only.
7. Compare classification models using suitable metrics and confusion matrices.
8. Interpret permutation importance and discuss the limitations.
9. Demonstrate one-record predictions with Streamlit.

## Dataset setup

1. Download the CSV from the [UCI AI4I 2020 dataset page](https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset).
2. Save it as `data/ai4i2020.csv`.

The target is `Machine failure` (0 = no failure, 1 = failure). Predictors used by the project are:

- `Type`
- `Air temperature [K]`
- `Process temperature [K]`
- `Rotational speed [rpm]`
- `Torque [Nm]`
- `Tool wear [min]`

Python 3.10 or newer is recommended.

```bash

source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```


## Run the project

Run commands from the repository root.

```bash
# Unit tests (synthetic test data; the raw CSV is not required)
python -m unittest discover -s tests -v

# Dataset cleaning summary and split details
python -m src.preprocessing

# Exploratory data analysis
python -m src.eda

# Baseline models: Logistic Regression and Decision Tree
python -m src.baseline_models

# Random Forest evaluation and permutation importance
python -m src.random_forest

# Compare all six classification models listed in the capstone guideline
python -m src.model_comparison

# Train and persist the preprocessing + classifier pipeline for the app
python -m src.train_model

# Start the Streamlit demo
streamlit run app.py
```

All dataset-dependent commands require `data/ai4i2020.csv`. The preprocessing command supports a custom CSV path:

```bash
python -m src.preprocessing --csv-path /path/to/ai4i2020.csv
```

## Models and evaluation

`python -m src.model_comparison` evaluates these six models on the same stratified split:

1. Logistic Regression
2. K-Nearest Neighbours
3. Decision Tree
4. Random Forest
5. Support Vector Machine
6. Naive Bayes

It writes:

- `outputs/model_comparison.csv` — compact metric comparison
- `outputs/model_comparison_details.json` — detailed classification reports and confusion matrices

The evaluation includes accuracy, precision, recall, F1-score, ROC-AUC, and confusion matrices. Since failures are a minority class, do not select a model by accuracy alone. Consider missed failures (false negatives), false alarms (false positives), and the intended maintenance trade-off. The held-out test set is for final evaluation, not hyperparameter tuning.

The notebook provides a guided three-model workflow, while `src/model_comparison.py` runs the full six-model comparison.

## Leakage prevention and preprocessing

The shared utilities in `src/preprocessing.py`:

- Validate the expected AI4I schema and binary target.
- Remove exact duplicate rows and rows with a missing target.
- Report feature missingness and IQR-based outliers; outliers are not automatically dropped because extreme sensor readings may be meaningful.
- Exclude identifiers `UDI` and `Product ID`.
- Exclude failure-mode flags `TWF`, `HDF`, `PWF`, `OSF`, and `RNF`, because they can reveal the failure target.
- Use a reproducible, stratified 80/20 split with seed 42.
- Fit median imputation and scaling for numeric features, and most-frequent imputation and one-hot encoding for categorical features, inside each model pipeline.

## Explainability

`python -m src.random_forest` produces permutation importance outputs under `outputs/`. Permutation importance estimates how shuffling one input feature affects the chosen evaluation score. It describes predictive usefulness on this evaluation; it does **not** establish causation.

## Limitations and future work

- AI4I is synthetic and may not represent every real industrial setting.
- Failure classes are imbalanced; the best threshold depends on the cost of missed failures versus false alarms.
- Model output probabilities are not necessarily calibrated real-world risks.
- Sensor conditions may omit maintenance history, environment, machine-specific differences, and operational costs.
- Before operational use, validate on real data, assess calibration and generalization, select thresholds on validation data, and establish monitoring and human review.
